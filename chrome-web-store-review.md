# Подання DAO Tools+ до Chrome Web Store

## Зміни для випуску 1.6.1

Що нового для користувачів:

- Popup: на головному екрані лишились підключення до сервера, калькулятор ліцензій і кнопка «Налаштування»; усі налаштування винесені на окремий екран із кнопкою «Назад».
- «Останні сервери» в popup: до 6 серверів, на які успішно входили з popup або кнопкою «Увійти в бекофіс» у Planfix. Показується назва закладу з картки, адреса — у підказці; кнопка поруч відкриває картку в Planfix або перемикає на вже відкриту вкладку з нею.
- Масштаб PiP-вікна 80–150 % у налаштуваннях popup, застосовується одразу.
- Нове вікно масового оновлення й перевірки ліцензій: підсумок по кожному серверу, «було → стало» по ліцензіях, повтор лише невдалих.
- Виправлено колір підсвічування задач у PiP-вікні.
- Калькулятор ліцензій сам обирає розгортання LT, якщо серед ліцензій сервера є перманентна.

Що змінити в кабінеті магазину:

- Пакет: версія 1.6.1. Нових дозволів і доменів немає: manifest.json відрізняється від 1.5.9 і 1.6.0 лише версією.
- Короткий опис, «Єдине призначення», alarms, desktopCapture, доступ до хостів і віддалений код — без змін.
- Замінити повний опис, обґрунтування tabs і storage текстами нижче: додано історію серверів, відкриття картки Planfix із popup і масштаб PiP.
- Скриншоти магазину: замінити ті, де видно старий popup (налаштування на головному екрані, без «Останніх серверів»).
- Політика конфіденційності: URL той самий, але вміст застарілий. Перевірка 01.11.2026: публічна сторінка (HTTP 200) має дату 27 квітня 2026, згадує daologistics.duckdns.org і не описує калькулятор, скриншоти та таблицю зайнятих ліцензій. Оновлена редакція від 25.09.2026 лежить у репозиторії SLM (`public-pages/dao-tools-plus-privacy-policy.html`), але не закомічена й не викладена. Перед поданням додати до неї абзац із розділу «Доповнення до політики для 1.6.1» нижче й опублікувати.
- Перевірку POST /license/pricing на production (25.09.2026 повертала HTTP 404 замість 401) 01.11.2026 не повторювали — перевірити калькулятор на production із погодженим пристроєм.
- Надати перевіряльнику тестовий доступ у закритому полі «Інструкції для тестування».

```text

Розширення об'єднує кілька робочих сценаріїв в одному інтерфейсі:
- додає в DAO Planfix кнопки та статуси для швидкого входу в legacy backoffice Syrve, відкриття Web: посилання окремою кнопкою Веб і окремої кнопки Веб:API для сторінки integrations, запуску Loyalty, підготовки й автозаповнення чернетки HelpDeskEddy, перевірки доступності сервера, отримання відкритого періоду з версією Syrve, перевірки стану ліцензій та запуску масових ліцензійних операцій у вікні з підсумком по кожному серверу, змінами ліцензій «було → стало» і повтором лише невдалих серверів;

- через popup дає змогу зберегти User ID, запросити персональний доступ для пристрою, активувати його кодом підтвердження, побачити поточний стан доступу, надіслати server context, прочитати або перемкнути режим і вручну показати останню діагностичну помилку;
- показує в popup до 6 останніх серверів, на які успішно входили з popup або з картки Planfix: назву закладу з картки, адресу в підказці й кнопку, що відкриває цю картку в Planfix або перемикає на вже відкриту вкладку з нею. Список зберігається лише локально й очищується кнопкою «Очистити»;
```

## Обґрунтування дозволів

### alarms

```text
Дозвіл alarms використовується для фонового оновлення статусу доступності DAO backend приблизно раз на хвилину в service worker. Розширення запускає періодичну перевірку, зберігає останній статус у локальному storage і оновлює індикатор action та дані popup без потреби тримати відкриту сторінку або popup.
```

### tabs

```text
Дозвіл tabs потрібен для керування робочими вкладками Syrve, Loyalty, HelpDeskEddy та внутрішніми сторінками розширення: калькулятором ліцензій і звітом зі скріншотом. Розширення читає URL службових вкладок, знаходить і повторно використовує відкритий калькулятор, створює та закриває тимчасові вкладки для відкритого періоду, версії й зайнятих ліцензій, перевіряє відповідність сервера контексту Planfix і визначає активну вкладку для Picture-in-Picture. З popup відкриває картку Planfix зі списку останніх серверів або перемикає на вже відкриту вкладку з нею. Дії запускаються з інтерфейсу розширення або пов’язаного робочого сценарію.
```

### storage

```text
Дозвіл storage зберігає локально User ID, client ID пристрою, request ID, персональний extension key, права доступу, робочі налаштування, останній server context, до 6 останніх серверів (адреса, порт, назва закладу та посилання на картку Planfix), статус backend, cooldown ручної діагностики, вигляд ліцензій, поріг зависання, налаштування й масштаб PiP та тимчасовий стан чернеток HelpDeskEddy. У chrome.storage.session тимчасово зберігаються скріншоти, звіти щодо завислих ліцензій, одноразові запити Groovy-скидання й контекст калькулятора: сервер, порт, Chain і результат перевірки ліцензій. Це дозволяє передавати дані між вкладками без повторного введення. Паролі Syrve в chrome.storage не зберігаються. Окремо тема калькулятора зберігається у localStorage його сторінки, а прапорець перевірки скидання — у sessionStorage сторінки Syrve.
```

### desktopCapture

```text
Дозвіл desktopCapture використовується лише після явної дії користувача у сценарії завислих ліцензій Syrve. Chrome показує системний вибір джерела захоплення; після підтвердження розширення створює один JPEG-скріншот. Залежно від сервера й обраної дії він додається до чернетки HelpDeskEddy або відображається на локальній сторінці звіту разом із текстом для ручного копіювання. Для інших серверів HelpDesk також використовується як fallback після невдалого скидання за наявності контексту Planfix. Скріншот тимчасово зберігається у chrome.storage.session. Постійний запис відео й фонове захоплення не виконуються; скасування вибору джерела завершує операцію без скріншота.
```

## Обґрунтування доступу до хостів

```text
dao.planfix.ua — поля карток і задач, службові дії, контекст сервера та Chain для калькулятора. syrve.app і *.syrve.app — Web/integrations та автологін. /resto на *.syrve.online, *.daocloud.it і http(s)://*.daocloud.fun — автологін, health і версія. http(s)://*/resto/service/monitoring/connections.jsp* — читання зайнятих ліцензій: IP, ПК, термінал, логін, модуль і Last activity; показ у Planfix та дії для завислих ліцензій. http(s)://*/resto/service/maintance/groovy.jsp* — одноразове вбудоване скидання 100/101 або 200; syrve.online заборонено кодом. hub.daolog.net і *.us-central1.hosted.app — PiP. planfix-to-syrve.com:8000 — popup/діагностика. slm.daolog.net — доступ пристрою, credentials, availability, CRM handoff, license API та JSON-прайс калькулятора /license/pricing. pro.helpdeskeddy.com — чернетки HelpDeskEddy. loyalty.syrve.live — автологін Loyalty.
```

## Віддалений код

```text
Ні. Усі JavaScript- і CSS-файли, які виконує розширення, постачаються всередині пакета розширення. Мережеві відповіді від https://slm.daolog.net і https://planfix-to-syrve.com:8000 використовуються лише як JSON або текстові дані для режимів, повідомлень і результатів службових операцій та не виконуються як код розширення. Groovy-скрипт для скидання завислих ліцензій також локально вбудований у код розширення і обмежений модулями 100/101 та 200.
```

## Технічний статус для рев'ю

```text
Захищений DAO backend опублікований на https://slm.daolog.net з актуальним TLS-сертифікатом. Чутливі робочі операції, зокрема request/claim потоки, extension key, перевірка стану доступу пристрою, видача облікових даних Syrve, CRM handoff, перевірки доступності, перевірки ліцензій і оновлення ліцензій, ідуть лише по HTTPS.

Внутрішній popup/backend на https://planfix-to-syrve.com:8000 використовується тільки для send_data, get_mode_description, toggle_mode і get_last_error; запит get_last_error виконується лише вручну з popup, а локальний cooldown цього запиту зберігається між відкриттями popup через chrome.storage.

Поточний Web flow більше не використовує окремий lookup веб-адреси на backend: розширення читає поле Web: посилання прямо з картки Planfix, відкриває відповідний *.syrve.app URL окремою кнопкою Веб і за потреби окремою кнопкою Веб:API відкриває integrations-сторінку /integration-management/index.html#/integrations, після чого виконує автологін на боці розширення.

Кнопка Довідники використовує той самий Web hostname, але не отримує логін і пароль у браузер для цієї операції: розширення викликає захищений маршрут /crm/handoff на SLM, а SLM бере першу активну service account, звертається до зовнішнього CRM API й повертає тільки перевірене одноразове посилання https://api.daolog.net/connect?ticket=....

Для масових ліцензійних операцій розширення або виконує inline-чергу через захищений DAO backend, або в legacy-форматі відкриває окрему робочу сторінку license manager у новій вкладці; у жодному з цих сценаріїв мережеві відповіді не виконуються як код розширення. Для завислих ліцензій на серверах не з домену syrve.online розширення після кліку користувача відкриває /resto/service/maintance/groovy.jsp і через одноразовий локальний запит виконує вбудований Groovy-скрипт LicenseService.releaseModuleConnections лише для модулів 100/101 або 200. Це відповідає поточним URL і сценаріям у manifest.json, background.js, popup.js і content scripts.
```


## Інструкції для перевірки калькулятора

1. Встановити пакет 1.6.1. У popup налаштувати тестовий User ID та активувати погоджений пристрій. Дані тестового доступу передавати лише через закрите поле магазину; цей документ їх не містить.
2. Відкрити тестову картку закладу або задачу у DAO Planfix. Натиснути «Калькулятор»: спочатку має пройти перевірка ліцензій, потім відкриється калькулятор із сервером, поточними ліцензіями й контекстом Chain.
3. Перевірити вхід через «Перевірити ліцензії» → кнопку калькулятора в модальному вікні, а також через popup.
4. Перевірити PRO/Enterprise, Cloud/LT, кількість фронтів, популярні та інші ліцензії, підказки Loyalty/Chain, безкоштовний SousChef у Cloud із впровадженням $150 та безкоштовні касові ордери/калькуляційні карти. Значення мають відповідати production-прайсу SLM.
5. Скопіювати відповідь клієнту. Ця дія не створює замовлення, не списує кошти й не надсилає повідомлення клієнту.
6. Натиснути «Увійти в бекофіс» у картці закладу, відкрити popup: у «Останніх серверах» з'явиться назва закладу. Клік по назві підставляє сервер, кнопка поруч відкриває картку в Planfix. «Налаштування» → «Масштаб PiP-вікна» змінює розмір вмісту PiP-вікна.
